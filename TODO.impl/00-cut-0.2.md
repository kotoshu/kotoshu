# 00-cut-0.2 — The First Functional Library

## Goal

Ship `kotoshu-0.2.0` — the first release where `gem install kotoshu`
works on any Ruby 3.1+ system with **no system dictionary dependency**.
One call, `Kotoshu.check("Hello wrold")`, auto-downloads the English
Hunspell dictionary on first use and returns correct results. The CLI
works end-to-end with proper exit codes.

0.1.0 proved the API shape. 0.2.0 delivers the promise: "just works,
no setup." For 0.2.0 the resolution machinery is English-only; the
code is language-agnostic so adding more languages is a content task
(shipping dictionaries in `kotoshu/dictionaries`), not a code change.

## Critical path — three phases

### Phase A — ResourceManager (foundation)

The Spellchecker today takes a single `Dictionary::Base` the user must
configure manually. Phase A introduces `ResourceManager` as the thing
that produces that dictionary (plus frequency data) from a language
code, using the existing `LanguageCache`.

1. **`ResourceBundle`** (`lib/kotoshu/resource_bundle.rb`). Plain
   value object — Struct or class with `language`, `dictionary`,
   `frequency`, `model` (nil for 0.2), `rules` (nil for 0.2),
   `cached`, `source_urls`. No hand-rolled `to_h` (project rule).
2. **`ResourceManager`** (`lib/kotoshu/resource_manager.rb`,
   autoloaded from `lib/kotoshu.rb`). API:
   ```ruby
   Kotoshu::ResourceManager.resolve(
     text: "Hello wrold",
     language: :auto,            # or "en", "de", nil
     want: %i[spelling frequency],
     offline: false
   ) # => ResourceBundle
   ```
   Internals: detect language via `Language::Identifier` when `:auto`;
   fetch dictionary via `LanguageCache.get(language)`; fetch frequency
   via `FrequencyCache.get(language)` when wanted; construct
   `ResourceBundle`. No new network code — the caches already
   download from `kotoshu/dictionaries` and `kotoshu/frequency-list-kelly`.
3. **Spellchecker accepts `ResourceBundle`.** Modify
   `lib/kotoshu/spellchecker.rb` to accept either a `ResourceBundle`
   (new path) or a `Dictionary::Base` (legacy path). Strangler-Fig —
   don't break the 0.1 API. Extract `dictionary` and `frequency` from
   the bundle; ignore `model`/`rules` (nil for 0.2).
4. **First-use UX.** When `LanguageCache` downloads, print
   `[en] downloading dictionary (X.X MB)…` to STDERR. One line per
   resource, not per byte. Suppress when `$stdout.tty?` is false and
   `KOTOSHU_QUIET` is set.
5. **Configuration.** Add to `Configuration::SCHEMA`:
   - `offline` (boolean, default `false`) — also via `KOTOSHU_OFFLINE=1`
   - `default_language` (string, default `"en"`) — used when
     `language: nil` and detection is inconclusive
6. **Offline mode.** `ResourceManager.resolve(..., offline: true)`
   only uses cached resources; raises `ResourceNotCachedError` with a
   message naming what's missing and how to pre-fetch.

**Phase A acceptance:** `Kotoshu.correct?("hello")` works on a Docker
`ruby:3.3` container with no `/usr/share/dict/words`, auto-downloading
en_US on first call.

### Phase B — English correctness

7. **Audit en_US fixtures.** Run
   `bundle exec rspec spec/hunspell_tests/ --tag lang:en` (or filter
   by fixture path). Record which examples fail and categorize:
   compound words, capitalization, affix combinations, special
   characters. This is `01` task 1 scoped to en_US only.
8. **Fix en_US failures.** Target the categories from the audit. The
   full MECE 4-layer refactor (`01` task 6) is explicitly **not**
   required for 0.2 — patch the procedural `algorithms/lookup.rb`
   where needed. Each fix gets a named spec example.
9. **Suggestion sanity.** Verify `Kotoshu.suggest("helo").first.word`
   == `"hello"` for the top-20 common misspellings. Tune
   `EditDistanceStrategy` weight or `frequency_bonus` if the top
   suggestion is wrong.

**Phase B acceptance:** 100 % of en_US Hunspell fixtures pass.
`suggest("helo")[0]` == `"hello"`.

### Phase C — CLI wired

10. **Wire `CheckCommand` as canonical `check`.** Remove the basic
    `check` from `lib/kotoshu/cli.rb`; register
    `Kotoshu::CheckCommand` (from `commands/check_command.rb`) via
    `subcommand "check", Kotoshu::CheckCommand`. This is `02` task 1.
11. **Exit codes** (`02` task 6):
    - `0` — no errors found
    - `1` — errors found
    - `2` — usage error
    - `3` — dictionary fetch failure (network down, not cached + offline)
12. **Flag reconciliation** (`02` task 5). For 0.2, support exactly:
    - `kotoshu check FILE` — default check, text output
    - `--language en|de|...|auto` — language selection (`auto` =
      detect via `Language::Identifier`)
    - `--format text|json` — output format (sarif deferred to 0.3)
    - `--offline` — use cached resources only
    Remove or hide every other flag the README mentions but code
    doesn't support yet. Update README to match.
13. **End-to-end CLI spec.** Under `spec/kotoshu/cli/`, using a temp
    dir (not real `~/.kotoshu`): write a file with known misspellings,
    run `kotoshu check`, assert exit code + output content for both
    `text` and `json` formats.

**Phase C acceptance:** `kotoshu check README.adoc` exits 1 with
readable error output; `kotoshu check clean_file.txt` exits 0.

## Release-level acceptance criteria

- Fresh `docker run --rm ruby:3.3` → `gem install kotoshu` →
  `ruby -e "require 'kotoshu'; puts Kotoshu.correct?('hello')"`
  prints `true` (auto-downloads en_US on first call)
- `Kotoshu.correct?("helo")` returns `false`
- `Kotoshu.suggest("helo").first.word` == `"hello"`
- `kotoshu check README.adoc` exits 1, reports errors with suggestions
- `kotoshu check clean.txt` exits 0
- en_US Hunspell fixtures: 100 % pass
- No system dictionary dependency (no `/usr/share/dict/words` read)
- `Kotoshu.check(text, offline: true)` raises clear error if not cached
- `ENV['KOTOSHU_OFFLINE']` == `"1"` respected throughout
- README accurately reflects 0.2 capabilities (no false claims)
- `bundle exec rspec` green; `bundle exec rubocop` clean

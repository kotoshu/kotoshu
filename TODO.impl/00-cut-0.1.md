# 00-cut-0.1 — The 0.1.0 Release Cut

## Goal

Ship `kotoshu-0.1.0.gem` to rubygems.org with a clear, honest scope: the
pure-Ruby API and CLI work for English via system dictionaries; everything
else is documented as in-progress.

This is **not** v1.0. The point of 0.1 is to be installable, runnable,
and discoverable — to claim the name on rubygems.org and establish the
public API shape.

## Release execution (manual — requires maintainer)

The global project rule is "AI never pushes tags, never pushes to main,
never publishes." The following must be run by a human:

```bash
# 1. On a clean main, verify everything passes
git checkout main
git pull
bundle install
bundle exec rspec
bundle exec rubocop

# 2. Verify VERSION
grep VERSION lib/kotoshu/version.rb
# Should read: VERSION = "0.1.0"

# 3. Build the gem
gem build kotoshu.gemspec
# Produces kotoshu-0.1.0.gem

# 4. Sanity-check the gem contents
gem contents kotoshu-0.1.0.gem --tarball

# 5. Tag (the human decides when)
git tag -a v0.1.0 -m "kotoshu 0.1.0 — first public release"
git push origin v0.1.0

# 6. Publish to rubygems.org
gem push kotoshu-0.1.0.gem

# 7. Cut a GitHub Release
gh release create v0.1.0 --notes-from-tag

# 8. Smoke test from a clean environment
docker run --rm -it ruby:3.3 bash -c '
  gem install kotoshu
  ruby -e "require \"kotoshu\"; puts Kotoshu.correct?(\"hello\")"
  echo "Hello wrold" | ruby -e "require \"kotoshu\"; puts Kotoshu.check(STDIN.read).errors.map(&:word)"
'
```

- `Kotoshu.correct?("hello")` returns `true` on a fresh install with
  no env vars set
- `Kotoshu.correct?("helo")` returns `false`
- `kotoshu check README.adoc` runs without crashing
- README has no false claims (license, model count, CLI flags)
- LICENSE and CHANGELOG.md exist
- rubygems.org page shows v0.1.0 with correct metadata

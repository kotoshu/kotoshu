# 58 — T5.2: Configuration as data, not singleton

## Goal

Drop the `Configuration.instance` process-wide singleton. The
singleton forces every test to call `Configuration.reset` in
before/after hooks, prevents per-document configuration, and makes
parallel test execution unsafe.

## Current state

`lib/kotoshu/configuration.rb` defines:

```ruby
def self.instance
  @instance ||= new
end

def self.reset
  @instance = nil
end
```

Every caller does:

```ruby
config = Kotoshu::Configuration.instance
config.cache_path = "/tmp/foo"
```

This is referenced from:
- `lib/kotoshu/spellchecker.rb`
- `lib/kotoshu/resource_manager.rb`
- `lib/kotoshu/cache/*.rb` (all cache classes)
- `lib/kotoshu/cli.rb`
- `lib/kotoshu/suggestions/strategies/edit_distance_strategy.rb` (was; now goes through FrequencyProvider)

## Target design

```ruby
# Configuration is a plain class. Callers create instances.
config = Kotoshu::Configuration.new(cache_path: "/tmp/foo")

# Spellchecker accepts config explicitly.
speller = Kotoshu::Spellchecker.new(config: config, resource_bundle: bundle)

# The Kotoshu module facade retains a process-default for ergonomics.
Kotoshu.configure { |c| c.cache_path = "/tmp/foo" }
Kotoshu.correct?("hello")  # uses process-default config
```

The facade keeps the simple API. Under the hood, it manages a
process-default `Configuration` instance instead of a global
singleton via `Configuration.instance`.

## Phases

### Phase A — Spellchecker accepts config kwarg

`Spellchecker.new(resource_bundle:, config:)` accepts a Configuration
instance. Default: `Kotoshu.configuration` (process-default managed
by the facade, not by `Configuration.instance`).

This is a non-breaking change: existing callers that omit `config:`
get the process default.

### Phase B — Migrate callers off Configuration.instance

Walk through `resource_manager.rb`, `cache/*.rb`, etc. Replace
`Configuration.instance` with config passed in via constructor or
method parameter. Each file becomes a separate PR (small, focused).

### Phase C — Deprecate Configuration.instance

Mark `Configuration.instance` as deprecated with a warning. Keep
the method for one release cycle, then remove.

## Acceptance criteria

- [ ] `Spellchecker.new` accepts `config:` kwarg.
- [ ] No production code calls `Configuration.instance` directly
      (only the facade does, for the process default).
- [ ] Tests no longer call `Configuration.reset` — they construct
      their own instance and pass it explicitly.
- [ ] `parallelize_me!` can be added to the spec suite without
      flaky failures.

## Why this matters

- **Test isolation.** Today, every test that touches configuration
  has to reset the singleton. Forgetting the reset causes cascade
  failures.
- **Per-document config.** Multi-document checking (TODO 52) wants
  per-document config (different personal dicts, different ignore
  lists). The singleton blocks this.
- **Parallelism.** `ParallelChecker` shares strategy instances
  across threads today; if strategies read `Configuration.instance`,
  that's a race waiting to happen once we add threads that use
  different configs.

## Dependencies

- **Blocked by:** none.
- **Blocks:** TODO 52 (multi-language document checking) benefits
  from per-segment config. TODO 56 T4.2 (CI matrix) — parallel
  specs become safe.

## Out of scope

- Changing the Configuration SCHEMA (already data-driven).
- Adding new configuration options.
- Removing the `Kotoshu.configure` facade method (kept for
  ergonomics).
